Layout mod - FIRST RUNNABLE BUILD (through Module 7b)
=====================================================

WHAT THIS IS
  All source built so far: the pure math layer, the data model, the four
  systems, the undo command set, the networking layer, the rendering pair,
  the UI pair (Module 6), and now Module 7a - the entry point
  (LayoutModSystem, the composition root) plus server/client configuration
  and the config wiring through the managers and the network handler.
  35 source files.
  Module 7b completes the mod: the tool item (ItemGuideTool), the
  interaction controller (GuideToolController - raycast, click routing,
  comatose grabs), hotkeys, and the asset tree (modinfo.json, itemtype,
  recipe, lang, modicon). After a clean build this is a RUNNABLE MOD -
  see HOW TO RUN IT below.

NEW IN 7a (no new DLL references needed)
  - src/LayoutModSystem.cs, src/Config/LayoutServerConfig.cs,
    src/Config/LayoutClientConfig.cs
  - Server config: layout.json is created with defaults in ModConfig on
    first server start. Client config: layout-client.json remembers the
    tool's last-used scale/projection/fill.
  - Design change (supersedes "ungated toggles"): while a guide is
    edit-locked, ALL mutations from other players are rejected - dispel and
    the property toggles included. Admins (controlserver) may override for
    atomic ops when adminCanOverrideLocks is true. Undo/redo respects the
    same gate.

WHAT YOU NEED
  - .NET 10 SDK.
  - Vintage Story 1.22 installed, for these DLLs (all ship with the game):
      VintagestoryAPI.dll   (install root)
      Newtonsoft.Json.dll   (Lib\ subfolder)
      protobuf-net.dll      (Lib\ subfolder)   <-- added for Module 4 networking

THE ONE THING TO CHECK FIRST
  Open Layout.csproj and look at the <VintagestoryDir> line. It is set to
      C:\Users\Zech\AppData\Roaming\Vintagestory
  the default Windows install location. If your game is installed elsewhere,
  change that one line to point at the folder that contains VintagestoryAPI.dll.

HOW TO BUILD
  1. Open a terminal.
  2. cd into this folder (the one containing Layout.csproj).
  3. Run:   dotnet build
  4. "Build succeeded. 0 Warning(s) 0 Error(s)" -> perfect. Otherwise copy the
     FULL output (it names the file + line) and paste it back.

IF IT CANNOT FIND Newtonsoft.Json.dll OR protobuf-net.dll
  Both normally live in the install's Lib\ subfolder, which is what the project
  expects. If a build complains one is missing, check whether your install keeps
  it directly in the install root instead, and if so remove the "\Lib" from that
  one HintPath in Layout.csproj.

NEW IN 7b
  - src/Client/GuideToolController.cs - all interaction: per-tick raycast
    while the tool is held, click routing by mode, live drag with local
    preview + 10 Hz throttled sends, and COMATOSE GRABS (swapping tools
    mid-edit suspends the grab without releasing the server-side lock;
    re-equipping resumes it if the guide and lock survived).
  - src/Items/ItemGuideTool.cs - stateless item; suppresses vanilla
    left/right actions and forwards clicks to the controller.
  - Hotkeys (all rebindable, all inert unless the tool is held):
      F        tool mode & settings GUI
      Ctrl+Z   undo        Ctrl+Y   redo
  - Assets: modinfo.json + modicon.png at mod root; assets/layout/ with
    the itemtype (borrows the vanilla abacus shape:
    game:block/clutter/abacus-pristine), lang, and the grid recipe:
    6 sticks (frame) + 3 metal nuggets of ANY metal (beads), 3x3:
        stick  stick  stick
        nugget nugget nugget
        stick  stick  stick

HOW TO RUN IT
  1. dotnet build   (as before; expect Build succeeded)
  2. Assemble the mod zip with these at the ZIP ROOT (not in a subfolder):
       modinfo.json
       modicon.png
       assets\           (the whole folder)
       Layout.dll        (from bin\Debug\net10.0\ or bin\Release\...)
  3. Drop the zip into %appdata%\VintagestoryData\Mods and start the game.
  4. First-run checklist:
       - Mod manager lists "Layout 0.1.0".
       - layout.json appears in VintagestoryData\ModConfig after first
         server/world start; layout-client.json after first client quit.
       - Craft or /giveitem: the tool shows abacus art. If it renders as
         missing-texture purple, or sits oddly in hand, use .tfedit to tune
         the transforms and tell me what the texture error log says.
       - Hold the tool: HUD appears. F opens the mode panel. Two clicks on
         the ground place your first arch.
  NOTE ON FIRST-RUN UNKNOWNS: the C# API surface was compile-verified, but
  itemtype JSON (shape/texture resolution, transforms) and the recipe only
  prove out in-game - those are the expected first-run tweak points.

IN-GAME FIXES (after first playtest)
  - Rendering: white texture bound to the standard shader (crosshair-tracking
    colours fixed), stage OIT -> Opaque with manual blending (translucency
    fixed), RgbaLightIn pinned white (black stretches fixed).
  - Draft preview: after the first anchor click you now see a live ghost of
    the arch from the anchor to your crosshair, built by the same pipeline as
    the real guide (incl. the Blue/Indigo far-foot shade). It updates as you
    aim and disappears on the second click, cancel, or tool swap.
  - Lock mode: clicks now target points ONLY, at double pick radius, so
    locking AND unlocking are reliable - a near-miss no longer silently does
    nothing (that was the "can't unlock" symptom).
